## 题目

给定一个 `n × n` 的二维矩阵 `matrix`，要求将其顺时针旋转 90°，且必须**原地**修改，不能借助另一个矩阵。

## 思路：先推导映射关系

旋转的本质，是每个元素从一个位置搬到另一个位置。所以第一步不是写代码，而是搞清楚：原来在 `(i, j)` 的元素，旋转后去哪了？

### 映射推导

对于矩阵中的任意元素 `(i, j)`，顺时针旋转 90° 后，它对应的新索引是：

```text
(i, j) -> (j, n - 1 - i)
```

这个结论可以拆成两部分来理解：

1. **原列变成新行**：原来的列索引 `j`，变成了新矩阵的行索引，即 `(..., j) -> (j, ...)`。直观地说，原矩阵的"左边"（第 0 列）转过去变成了新矩阵的"顶边"（第 0 行）。
2. **原行变成新列，但方向反了**：原来的行索引 `i` 变成了新矩阵的列索引，方向相反，即 `(i, ...) -> (..., n - 1 - i)`。也就是说，原矩阵的"顶边"（第 0 行）转过去变成了新矩阵的"右边"（最后一列）。

这两条规律合起来，就是 `(i, j) -> (j, n - 1 - i)`。

### 拆成两步

一次性把元素搬到最终位置会覆盖掉别的元素（除非做环状替换，比较绕）。更简单的方式是把整个变换拆成两步，每一步都只涉及两两交换：

1. **主对角线翻转**：负责"行列互换"，即 `(i, j) -> (j, i)`。这一步之后，原行变成了新列，原列变成了新行。
2. **水平翻转**：负责"调整方向"，保持行不变，把列索引 `i` 变成 `n - 1 - i`，即 `(j, i) -> (j, n - 1 - i)`。

两步叠加，正好得到 `(i, j) -> (j, n - 1 - i)`。而且两步都是"对称交换"，天然适合原地操作。

## 代码实现

```java
class Solution {
    public void rotate(int[][] matrix) {
        // 根据数学关系可知：对于矩阵中的一个元素 (i, j)
        // 顺时针翻转 90° 后对应元素索引为 (j, n-1-i)
        int n = matrix.length;

        // 第一步：主对角线翻转（行列互换），只需遍历下三角
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < i; j++) {
                int temp = matrix[i][j];
                matrix[i][j] = matrix[j][i];
                matrix[j][i] = temp;
            }
        }

        // 第二步：水平翻转（每行左右互换）
        // 这里为了保持数学映射的一致性，用 j 表示行、i 表示列
        for (int j = 0; j < n; j++) {
            for (int i = 0; i < n / 2; i++) { // 列只需遍历一半
                int temp = matrix[j][i];
                // 列索引 i 变成 n - 1 - i
                matrix[j][i] = matrix[j][n - 1 - i];
                matrix[j][n - 1 - i] = temp;
            }
        }
    }
}
```

## 复杂度

- **时间复杂度**：O(n²)，主对角线翻转约 n²/2 次交换，水平翻转约 n²/2 次交换，总量仍是 n² 级别。
- **空间复杂度**：O(1)，只用了常数个临时变量，满足"原地"要求。

## 小结

这道题的关键不在代码，而在把几何变换翻译成坐标映射。一旦推导出 `(i, j) -> (j, n-1-i)`，剩下的就是把它拆成两个对称操作。这种"先找数学关系、再拆解步骤"的思路，比死记硬背旋转公式可靠得多——换个方向旋转（逆时针、180°）也能自己推出来。
